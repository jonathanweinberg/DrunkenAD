# Issue 005: Get-Help Should Be A First-Class Resource

Status: Fixed in v0.13.0

## Summary

GitHub issue #5 requested that `Get-Help` become a first-class resource for
DrunkenAD users. The module already had basic comment-based help, but it did not
define a release contract for help quality, did not ship a module-level
`about_DrunkenAD` topic, and did not test help as part of the public surface.

## Evidence

- Users at a PowerShell prompt need command syntax, parameter guidance, examples,
  and related commands without leaving the shell.
- Compatibility commands need complete help because older scripts may still call
  them directly.
- The previous test suite checked exports and release readiness, but did not
  fail if command help regressed to autogenerated content.

## Desired Outcome

- Treat comment-based help as the command help source of truth.
- Keep help blocks directly attached to exported functions.
- Add a module-level `about_DrunkenAD` topic for discovery and workflow
  orientation.
- Test `Get-Help` output for every exported command.
- Release the work as `v0.13.0`.

## Fix Notes

- Added `tests/Help.Unit.Tests.ps1` to validate `Get-Help` output instead of
  only checking source text.
- Expanded comment-based help on every exported command with synopsis,
  descriptions, explicit parameter help, examples, inputs, outputs, related
  links, component metadata, role metadata, and functionality metadata.
- Added `DrunkenAD/en-US/about_DrunkenAD.help.txt` as the module-level help
  topic.
- Updated README, docs index, and testing docs so `Get-Help` is part of the
  normal user and operator reading path.
- Updated release metadata and release-readiness checks for `v0.13.0`.
